# Architecture and code explanation

This document maps each recommendation from the preceding design audit into a separate module. Every algorithm runs client-side and produces SVG markup; no compiled dependencies or external data feeds are required.

## 1. `/misc/` page integration — `index.html` and `style.css`

The site already has a fixed scarf navigation that is generated by `/assets/site-nav.js` and styled by `/assets/site.css`. At desktop sizes, it occupies `min(32vw, 430px)` on the right and has a high `z-index`. The previous experiment used almost the full viewport and put the controls under that rack.

The new `misc-shell` uses `width: min(1240px, calc(100% - var(--scarf-rack-width) - 74px))` at desktop sizes. Because the width excludes the rack plus clearance, the controls remain to its left. At 1240px and below, the shared site switches scarves into a horizontal scrolling rack. The page then reserves `padding-top: 132px` (112px on mobile) before its own content. Below 850px, the control panel becomes a second row rather than a narrow third column. Nothing globally is modified.

The ornament is a normal `<section>` within `<main>`. A future `/misc/` project can be another section below it. Its SVG remains transparent even though the page background is cream.

## 2. Shared geometry — `js/core.js`

`M.rng(seed)` implements a local xorshift seeded random generator. There is no `Math.random()` during artwork construction. `M.childSeed(root, salt)` produces **independent random streams**, so adding leaf details cannot inadvertently reshuffle every knot.

`M.bezier(a,b,c,d,t)` evaluates a cubic Bézier at parameter `t`:

```
B(t) = (1-t)^3 A + 3(1-t)^2 t B + 3(1-t)t^2 C + t^3 D
```

`M.tangent(...)` evaluates its derivative and normalizes it. `M.normal(tangent)` rotates a tangent by 90°, which is needed for variable-width silhouettes.

`M.wave(...)` samples both *position and tangent from the same curve*. This fixes a problem in v7: the previous vine stroke was curved, but some secondary parts were attached using straight-line interpolation.

## 3. Scene planning — `js/composition.js`

`M.plan(settings, rng)` first chooses a focal area and scale, then creates one to three primary botanical curves and independent positions for larger interlace regions. It uses separate rules for botanical, decorated-letter, and interlace modes.

The focal ellipse is not a visible frame. It serves as an **exclusion zone** so secondary foliage does not indiscriminately cover the letter. Main stems may run near it; small branches skip tips that would obscure its interior. Plan objects contain `bounds`, `focal`, `center`, `glyphSize`, `stems`, `knots`, and `detail`.

There are several candidate root directions (from bottom, top and sides), shuffled by the seed. Stems no longer automatically connect the four edges into a square. Every stem is defined by four Bézier points and a base width. The preview still varies within a bounded page-shaped drawing field, not an infinite canvas.

## 4. Botanical anatomy — `js/botany.js` (updated in Pass 1 / v9)

The scene planner still creates the main cubic Bézier routes. `organicSpine()` subtly displaces the points sideways along the normal of the route, applying low-frequency bending that vanishes at the endpoints, and then recomputes each tangent from adjacent displaced points. This matters because leaves must follow the *actual drawn route*, not an underlying straight segment.

`stemOutline()` turns sampled centerlines into filled, variable-width silhouettes. Two edge lists are generated using the local normal. The approximate width law is `tipWidth + (rootWidth-tipWidth)*(1-t)^1.18`. The starting region is broad, while the tips narrow to hairline widths. The rendering adds bark striations and selective longitudinal highlights.

`primaryShoot()` creates branches that begin roughly aligned to their parent stem and turn outward through cubic control points. `secondaryTwig()` adds fine branching at one additional level. This recursion is capped intentionally to keep detail count and SVG complexity bounded.

`leafSilhouette()` constructs four leaf families directly as SVG paths: acanthus, miniature acanthus, lanceolate and trumpet. The shapes include alternating lobes, notches and asymmetry. All leaves are drawn in local positive-X coordinates and rotated once according to their attachment tangent. `leafEngraving()` supplies fine veins, scratch hatching and varied line weights; larger leaves receive clipped pigment speckles.

`terminalScroll()`, `berryRosette()` and `bud()` attach ornament to actual branch endings. Main roots also receive larger basal acanthus foliage to reduce the appearance of stems cut off at a square edge.

Dense growth is organized into a *hierarchy* of large stems → medium shoots → small twigs → leaves → penwork, rather than a flat layer of randomly positioned marks. Branches are shortened or omitted near the protected focal region and the canvas edges.

The module's public interface and its position in the pipeline are unchanged: `M.botanical(plan, settings, seededRandom) -> SVG markup`.

For details of the v9 adjustments, performance constraints and testing scope, see `PASS_1_BOTANY.md`.

## 5. Insular initial — `js/initials.js`

`M.initial()` renders an uppercase character and uses the same glyph as a clipping region for tiny lines, internal knotwork and pigment traces. The fill is an opaque, muted mineral color with a rough outline: **no bevel, metallic gradient, or fake shine**. Small terminal spirals connect to its vicinity.

The interior knotwork is generated by the same real crossing engine used for standalone interlace, then clipped to the letter itself. This is fundamentally different from displaying an unrelated square knot next to a large letter.

The glyph outline still comes from a system serif font (Georgia/Palatino fallback). Although its interior is decorated, it is **not yet a hand-constructed Book of Kells letter alphabet**. A later refinement could use custom scanned/vectored initial outlines, preserving the rest of the pipeline. The CSS-like web effects are retained in SVG so browser export can reproduce them.

## 6. True interlace — `js/interlace.js`

This engine is adapted from the open-source Celtic Knot Maker approach. It operates on a *doubled square grid*. Positions alternate between crossings and break locations. A break can reconnect strands horizontally or vertically, turning a field of diagonal plaits into closed ribbon paths.

`knotGrid()` creates the break pattern, traces connected loops, and optionally tries reconnections that reduce the number of strands. `renderKnot()` maps grid coordinates to a smooth geometry and draws every closed path. At each proper crossing, one segment is repainted above the other, giving real alternating over-under interlace.

The mode uses multiple panels of different sizes. The decorated initial also calls the knot engine internally. At high settings, independent panels can still look like knots arranged near each other; more ambitious shaped knot domains (irregular curved windows and a whole custom lettering construction system) would require changes to the graph topology, not merely clipping.

The adapted algorithm retains its MIT notice in `THIRD_PARTY_LICENSES.md`.

## 7. Material color — `js/pigment.js`

`M.mix(a,b,t)` chooses Spectral.js v3 when present as `window.spectral` and falls back to a fast per-channel Kubelka–Munk approximation if it is absent. Neither method simply linearly interpolates sRGB.

`M.painted(id, outlinePath, baseColor, bounds, settings, rng)` creates a `<clipPath>` of the ornament silhouette, fills the whole shape with opaque color, and overlays sparse secondary pigment, grain and pale flecks **only within the clipped shape**. The background remains completely transparent.

This replaces v7's free-floating mosaic rectangles. The distorted Instagram reference can be expanded in a later phase through more aggressive posterization, gradient mapping or channel misregistration, but its baseline rule should remain: texture belongs to specific painted forms rather than arbitrary positions in the canvas.

To keep render size and performance reasonable, leaves use a lightweight texture path with fewer flecks than a large stem.

## 8. Print and ink effects — `js/finish.js`

`M.finishDefs()` defines exportable filters. In `#press`, a blur is applied to `SourceAlpha`; a discrete `feComponentTransfer` thresholds it into a sharper enlarged silhouette; turbulence and `feDisplacementMap` create irregular edges; a dark flood is clipped against that resulting mask. The dark spreading edge is merged *under* the original colored art.

This matters: v7 composited the altered alpha with the source artwork in a way that could erase the extension outside the original silhouette. The new merged edge can actually exist outside it.

The `distortion` slider adjusts displacement intensity. `print wear` affects wear and erosion in the pigments and the filtering. The `ink bleed` checkbox controls the alpha/edge extension separately.

Potential issue: SVG filters can differ across Safari, Chrome, Firefox, Illustrator, and older rasterizers. Browser-rasterized PNG is the stable visual fallback. High distortion settings can still impair legibility; the default is intentionally restrained.

## 9. Composition and overlap checking — `js/render.js`

The compositor receives one scene plan and renders elements in meaningful layers: interlace backdrop where needed; decorated initial; connected botanical strokes; bounded accent rosettes; optional, mostly peripheral letter fragments. A `focal` ellipse protects letter readability, while bounded site positions avoid the canvas edges and other large knot fields.

The code uses deterministic spatial tests, not a full physics solver. It reduces collisions but does not guarantee mathematically non-overlapping regions. Some selective botanical overlap is desirable in manuscript illumination. This is an intentional constraint rather than a claim of flawless collision detection.

The `letter fragments` control is intentionally sparse. It never generates a fixed decorative title, an invented manuscript passage or AI-sounding caption in the artwork.

## 10. UI and export — `js/app.js`

Controls form an explicit settings object. `M.render(settings)` is a pure function of those settings and the loaded modules. Input is debounced (75ms), so moving sliders doesn't launch dozens of heavy renders per second.

SVG is assembled as markup with no external linked images. Saving SVG downloads this markup. For PNG, the browser builds a Blob URL, loads it as an `Image`, paints it to a 3200-pixel-wide canvas, and downloads the PNG. The alpha channel remains transparent by default. Selecting nontransparent export inserts one cream rectangle at the back of the SVG before rasterization.

The editor isn't saving online state or uploading generated artwork. Seeds and inputs are the reproducible recipe. `something else ↗` uses `crypto.getRandomValues` (with a fallback) only to choose the next seed.

## 11. All modules working together

```
index.html + style.css / existing site assets
                |
                v
         app.js: settings
                |
                v
      composition.js: scene plan
                |
                v
      render.js: orchestrator
         /        |         \
  initials.js  botany.js  interlace.js
         \        |         /
          pigment.js + core.js
                |
          finish.js filters
                |
          transparent SVG
                |
            app.js export
            /         \
           SVG       PNG (Canvas)
```

This is a complete, testable module boundary. To replace the leaves, edit only `botany.js`. To improve letter construction, edit only `initials.js`. To add another compositional grammar, define it in `composition.js` and add its layer strategy in `render.js`. To tune the physical print look, edit `finish.js` and `pigment.js`.
