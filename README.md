# keegan.biz — homepage + sitewide notes

## What this site is

keegan.biz is a personal site built as a collection of separate pages rather than one fixed portfolio template.

The shared system stays simple:
- cream paper background
- Helvetica / Arial
- red, green, yellow, black
- hard edges
- large type
- minimal interface chrome
- page-specific artwork and interaction do most of the visual work

Main colors:

- paper: `#ece7d7`
- ink: `#11110f`
- yellow: `#fdb913`
- green: `#006a44`
- red: `#c1272d`

## Shared site files

### `/assets/site.css`

Sitewide CSS.

Use this for things that should be shared across pages, especially navigation and global variables / base styles.

### `/assets/site-nav.js`

Shared navigation.

Pages can include an empty nav element:

```html
<nav data-site-nav></nav>
```

`site-nav.js` fills it in.

This keeps page names, links, and live / unfinished page behavior in one place instead of rewriting the navigation on every page.

### Page CSS

Each page can still have its own stylesheet.

Homepage:
```text
/style.css
```

Photography:
```text
/photography/style.css
```

etc.

The homepage currently loads:

```text
/assets/site.css
/style.css
/assets/sports/sports.css
```

The homepage also has a large inline `<style>` block for the chess and sports panels.

## Navigation

The navigation is generated by `/assets/site-nav.js`.

Live links should navigate normally.

Unfinished links are handled by the WIP system.

The WIP code listens for link clicks. A link with:

```html
data-live-link
```

is allowed through normally.

A link without it is treated as unfinished and opens the WIP overlay instead.

Keep that distinction intact when adding or activating pages.

## WIP overlay

Assets:

```text
/assets/home/crickets.mp3
/assets/home/horse.gif
```

The overlay says:

```text
sorry, i'm still working on this page.
```

Behavior:

1. unfinished link is clicked
2. normal navigation is cancelled
3. page content is hidden
4. cricket audio starts
5. horse is initially invisible
6. horse begins fading in at about 12 seconds
7. horse reaches full opacity at about 20 seconds
8. `horse.gif` keeps looping normally

Closing the overlay:

- stops the animation loop
- pauses the cricket audio
- resets audio to `0`
- hides the horse again
- removes the overlay
- restores the page

The WIP overlay is intentionally simple now.

Do not restore the older texture / duplicate-horse / color-processing version unless that is a deliberate new project.

## Chess panel

Opened with:

```text
chess?
```

Opening chess closes the sports panel first.

Main libraries:

- `chess.js` — board state and legal chess moves
- Stockfish — computer opponent
- Matter.js — captured-piece physics

Stockfish runs in a Web Worker from:

```text
/assets/chess/stockfish-19-lite-single.js
```

Famous autoplay games come from:

```text
/assets/chess/famous-games-pgn.js
```

### Chess modes

#### local

Two people play on the same device.

The board handles normal chess rules through `chess.js`.

#### computer

Play against Stockfish.

Current difficulty choices:

```text
easy
medium
hard
```

The easier modes choose from several Stockfish candidate moves with weighted randomness.

Hard mode uses a stronger direct Stockfish result.

#### autoplay

Replays selected famous games from the local PGN library.

The game is stepped through automatically rather than generated by Stockfish.

### Board behavior

The board supports:
- legal move highlighting
- piece selection / movement
- promotion
- board flip
- clocks / time setting
- reset
- resign
- result screen
- move review after a game

Captured pieces fall into the side capture area using Matter.js physics.

The page rebuilds the capture boundaries on resize so the physics area still matches the layout.

### Chess colors

Yellow:
white-side pieces

Green:
black-side pieces

Red:
board lines, controls, interface accents

The naming is chess logic internally, but the visual sides are yellow and green.

## Sports panel

Opened with:

```text
sports?
```

Opening sports closes the chess panel first.

Shared files:

```text
/assets/sports/sports.css
/assets/sports/sports.js
```

The panel itself lives on the homepage.

Football data is loaded through the sports helper in `sports.js`.

The current system uses FotMob-derived match / table data and keeps a lightweight saved copy so the page does not need to hit remote feeds for every normal view.

Yankees data uses MLB's public StatsAPI.

While the sports panel is open:
- live Yankees games can refresh about every 30 seconds
- preview / upcoming games can refresh about every 60 seconds

Closing the sports panel stops that live refresh loop.

## Homepage CSS split

There are three levels to remember:

```text
/assets/site.css
        ↓
/style.css
        ↓
inline homepage styles in index.html
```

`site.css` is shared.

`style.css` handles the main homepage hero and WIP layout.

The inline block currently contains most of the chess / sports layout and responsive rules.

If a style seems to ignore `style.css`, check the inline homepage styles before assuming the CSS is broken.

## Mobile

Homepage mobile behavior is mostly handled at `700px` and below.

Important points:

- hero padding reduces
- safe-area insets are included
- welcome type scales down
- WIP overlay becomes tighter
- chess and sports panels become full-width
- chess board / capture column scale down
- controls use smaller type and tighter grids

Do not rely on hover for anything necessary.

Hover styling should stay inside:

```css
@media (hover: hover) and (pointer: fine)
```

when possible.

## Before changing the homepage

Check these after every major edit:

- homepage still loads
- shared navigation appears
- live links navigate normally
- unfinished links open the WIP overlay
- cricket audio resets after closing WIP
- horse fade still works
- chess opens and closes
- sports opens and closes
- opening one panel closes the other
- local chess works
- computer chess can load Stockfish
- autoplay can load the famous-game library
- captured pieces still render
- sports data still loads
- mobile layout still fits
- no horizontal page overflow

Keep changes local when possible. Do not rewrite working chess, sports, navigation, or WIP code to change an unrelated homepage detail.
